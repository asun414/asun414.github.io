# 故障排查

## 无法识别 node 或 npm

关闭并重新打开 VS Code，再运行：

```powershell
node --version
npm --version
```

仍无法识别时，确认已安装 Node.js LTS，并在安装程序中启用添加到 PATH。

如果 PowerShell 阻止 `npm.ps1`，可临时使用：

```powershell
npm.cmd run dev
```

## 4321 端口被占用

Astro 通常会自动选择下一个端口。也可关闭旧终端中的开发服务器，或运行：

```powershell
npm run dev -- --port 4322
```

## 构建失败

先阅读终端中第一条错误，通常会显示文件路径和行号。依赖异常时可先运行 `corepack pnpm install`，再执行：

```powershell
npm run check
npm run build
```

不要手工修改 `dist/` 来掩盖源代码错误。

## Git push 被拒绝

若提示远程包含新提交：

```powershell
git pull --rebase origin main
git push origin main
```

出现冲突时不要使用强制推送。先在 VS Code 中逐个解决带冲突标记的文件，再重新检查、提交和推送。

## GitHub Actions 失败

打开仓库的 Actions 页面，进入最新一次失败记录，查看红色步骤。常见原因是构建错误、依赖安装失败或文件路径大小写不一致。在 Windows 本地可用并不保证 Linux 部署环境能接受错误的大小写。

## hlsun.org 无法访问

先检查 [GitHub Actions](https://github.com/asun414/asun414.github.io/actions) 是否成功，再检查 GitHub Pages 的 Custom domain 是否仍为 `hlsun.org`。Cloudflare DNS 应保持四条 GitHub Pages A 记录，以及 `www` 指向 `asun414.github.io` 的 CNAME。

## 回退错误更新

不要使用 `git reset --hard` 或强制推送。优先使用：

```powershell
git log --oneline
git revert <错误提交的编号>
git push origin main
```

`git revert` 会生成一个可追踪的撤销提交，适合已经发布的版本。
